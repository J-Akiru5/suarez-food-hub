Role Definitions

Each role has a specific app, capabilities, and responsibilities within the system

👤

Customer

Web App (:3000)
  • Browse menu with category filters & search (typo-tolerant)
  • View product descriptions, ratings, variants (size/sugar/preparation)
  • Add to cart with variant selection & quantity
  • Checkout with COD or GCash payment
  • Track order status in realtime with timeline UI
  • Cancel order if COD (before confirmed)
  • Rate rider after delivery (1-5 stars + comment)
  • Rate individual products (1-5 stars + comment per product)
  • View order history (All / Active / To Review / Reviews tabs)
  • Manage profile: name, phone, address, password change
  • Receive notifications on order status changes
  • Contact page, feedback form
🔑

Admin

Admin App (:3001)
  • Dashboard with revenue charts, order stats, top products
  • View all orders with realtime updates & filtering by status
  • Verify/reject payment status (COD: verified, GCash: pending → verified)
  • Confirm orders (notifies staff via notification)
  • View order details: items, customer, payment, rider, delivery proof
  • Approve/reject rider applications (rider_status: pending_approval → available/rejected)
  • Mark riders as resigned, delete obsolete riders
  • Manage staff accounts (view list — creation handled in-app)
  • View rider details: contact, vehicle, license, valid ID image
  • View & manage rider reviews (from customers)
  • View business reports (filterable, with PDF download)
  • Process rider cashout requests
  • Read customer feedback
  • Update business settings (name, address, phone, email, delivery fee, delivery radius, etc.)
  • Cannot: update kitchen order status (staff does that)
  • Cannot: assign riders to orders (staff does that)
  • Cannot: add/edit products (staff does that)
👨‍🍳

Staff (Kitchen)

Staff App (:3002)
  • Dashboard with order counts (pending, preparing, ready, completed today, low stock alerts)
  • Clickable status tiles link to filtered order views
  • View all orders with realtime subscription + 15s polling fallback
  • Update kitchen status: Confirm → Start Preparing → Ready for Pickup
  • Invite/assign multiple riders to an order (first to accept wins)
  • View assigned rider status & reassign if needed
  • View delivery proof photo with magnifying glass modal
  • View delivery location (text + Google Maps link)
  • CRUD products: Add, edit, delete (soft-delete) products with variants
  • Manage product variants (size, sugar level, preparation type with prices & stock)
  • CRUD categories: Create, edit, delete categories
  • Quick stock edit (+/- buttons + save) per product
  • Upload product images to Supabase Storage
  • Cannot: verify payment (admin only)
  • Cannot: change order status beyond kitchen flow
🛵

Rider

Rider App (:3003)
  • Dashboard: today's deliveries & earnings, weekly earnings chart
  • Available deliveries: view orders staff assigned, Accept or Skip
  • Active delivery: customer info, address, payment details, map navigation
  • Status flow: Accept → Start Delivery → Near Customer → Mark Delivered
  • Proof of delivery: take/upload photo before marking delivered
  • Call customer directly (tap-to-call)
  • Navigate to customer via Google Maps (tap-to-navigate)
  • Full order detail page: items, customer info, delivery address
  • Deliveries list: search, filter (All/Active/Pending/Completed), sort, map view
  • Earnings page: today/week/month/all-time earnings, weekly chart, cashout requests
  • Request cashout: specify amount & GCash number
  • View cashout history & status
  • Profile: edit name, phone, vehicle info; sound/vibration toggles
  • Pull-to-refresh on mobile
  • Realtime order updates with sound & vibration alerts
  • Automatic location tracking while on active delivery

End-to-End Workflows

How actions ripple across apps and roles from order to delivery

📋
Workflow 1: Customer Order Placement
The customer browses the menu, adds items to cart, checks out, and the order enters the system. Stock is checked on placement but not deducted — deduction happens when staff confirms.
1

Browse Menu & Add to Cart

Customer opens Web App, browses products by category, searches with typo tolerance, clicks a product to see description & variants (size/sugar/preparation), selects options, and adds to cart.

Staff receives notification, starts preparing, marks ready, then assigns riders. Kitchen status updates are visible to customer in real-time.

Status Transition Rules

Data Flow Map

How actions in each app affect the other apps — the complete data flow

📦 Customer Places Order

Web App → POST /api/orders → Supabase (orders table)
Supabase Realtime → Notifies → Admin App (real-time update)
Admin App → Can view & confirm → Notification sent to Staff App

👨‍🍳 Staff Updates Kitchen Status

Staff App → PATCH /api/orders → Supabase (orders.status)
Supabase Realtime → Updates → Web App (customer sees new status)
Supabase Realtime → Updates → Admin App (admin sees progress)

🛵 Staff Invites / Assigns Riders

Staff App → Updates pending_riders → Supabase (orders.pending_riders)
Staff App → Inserts notification → Supabase (notifications table)
Rider App → Realtime receives → Available Deliveries section
Rider App → Accept → updates rider_id → Other riders lose access

🛵 Rider Completes Delivery

Rider App → Uploads photo → Supabase Storage (delivery_proof)
Rider App → POST /api/orders/status (delivered) → Supabase (orders)
Supabase → Insert → rider_earnings (delivery fee earned)
Realtime → Updates → Web App (customer sees Delivered), Admin, Staff

⭐ Customer Submits Reviews

Web App → Insert → rider_reviews table
Web App → Insert → product_reviews table
Admin App → Reads → Reviews page (view all ratings)

📦 Staff Manages Inventory

Staff App → CRUD → products & product_variants tables
Staff App → CRUD → categories table
Web App Menu → Reads → Products + Categories (updated instantly)
Staff confirms order → Deducts stock → products / product_variants

⚙️ Admin Updates Settings

Admin App → PUT /api/settings → business_config table
Web App Footer → GET /api/settings → Displays dynamic footer content
Rider App → Reads → base_lat, base_lng for navigation origin

🚴 Rider Applies & Gets Approved

Web App Register → Creates profile → rider_status: pending_approval
Admin App → Approves/Rejects → rider_status: available/rejected
Admin App → Creates notification → Rider notified of approval/rejection
💡
Key Principle: All apps read from and write to the same Supabase database. Realtime subscriptions ensure every app stays synchronized. Staff writes to products/categories → Web Menu reads updated data. Admin writes to business_config → Web Footer displays it. Rider uploads proof → Admin & Staff see it instantly.
