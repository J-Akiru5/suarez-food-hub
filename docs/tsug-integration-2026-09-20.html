Accepted Risks (D2)

  • get_email_by_username RPC — anon-callable, allows email lookup by username without auth. Pre-existing; not deleted per D2. Should be addressed as a separate hardening task (RLS policy or RPC deprecation).
  • lookupUsername actions in admin/staff — server-side username-to-email lookup still present. Frontend no longer uses it (all login is email-only now), but the code remains.

Known Limitations (flagged, not changed)

  • Restore loop is non-atomic — concurrent cancellations could double-restore. Symmetric with deductStockForOrderIfNeeded which is also non-atomic. Would need a DB-level RPC to make atomic.
  • Request shape mismatch — admin PATCH sends {id, status}; staff PATCH sends {order_id, status}. Both work correctly but the inconsistency is a minor API ergonomics issue.
  • No test for restoreStockForOrder — would need a stub Supabase client. Flagged for future unit test addition.
